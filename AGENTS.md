# AiWorkShop-Live

Experimental fork of `C:\VIBE\AiWorkShop` (repo aymanalburaidi/AiWorkShop) to replace Zoom: live presenter audio, attendee mic on raised hand, then screen share, all inside the deck and the attendee portal. Every session is remote; there is no in-room audience.

## Isolation (read first)
- Never edit `C:\VIBE\AiWorkShop` or push to its repo from here. Changes flow one way: port proven features back by hand, later, only when the user asks.
- Room is `live-lab` (key in `secrets/presenter-key.txt`). Never read or write rooms `hs7-ai` or `hs7-ai-test`.
- Supabase project is shared with AiWorkShop: never alter existing `aiws_*` tables, functions or policies (the live workshop depends on them). New objects for this experiment use the prefix `aiws_live_`.
- No short link: the QR and displayed URL point at this repo's Pages site.

## Inherited from AiWorkShop

Workshop deck (desktop, presenter screen) + participant phone page (iPhone-first), published via GitHub Pages from `docs/`.

## Rules
- All user-facing text lives in `content/*.md` (one file per slide, `## field` sections). Never hardcode copy in `src/*.html`; add a field and reference it as `{{file-id.field}}`.
- `docs/` is build output. Edit `src/` + `content/`, then `pnpm run build`. `pnpm run deploy` builds, commits and pushes.
- Deck targets desktop only (min-width 1100px). The phone page (`src/join.html`) must work on iOS Safari: inputs >= 16px, safe-area insets, no hover-only actions.
- Max font weight 500 (Tajawal 300/400/500). Colors: MoE brand guide 2025 tokens in `:root`.
- Arabic copy follows the stop-slop Arabic rules: no em dash, straight quotes "...", no filler. Audience is female teachers, but keep buttons and instructions gender-neutral (verbal nouns: إرسال، نسخ، بدء); feminine only where factual (المتدربات، الطالبات).
- Supabase project `dqedhfwaquqaddbtfvtx` (QProjects) is shared with other apps. Only touch objects prefixed `aiws_`. Presenter actions go through `aiws_*` RPCs that check the room secret.
- Presenter notes page: `src/notes.html` → `docs/notes/`, gated by the presenter key via `aiws_verify`; timings from `content/21-presenter-page.md`. It follows the deck's slide over a key-derived realtime channel; the presenter only reveals that slide's notes one by one (Space/↓), with ←/→ as a backup remote for the deck.
- Presenter notes format: each slide file's `## notes` is an ordered list, one line per note: `- type | text`, in delivery order. Types (`say`, `do`, `ask`, `watch`, `go`) are declared in `presenter-page.note_types`; an unknown type fails the build. End each slide with a `go` line (the bridge sentence to the next slide). Notes address the presenter (masculine imperative); quoted lines are what he says to the audience.
- Live reactions (phone bottom bar: agree, disagree, raise hand) use no tables: thumbs are Realtime broadcast events (`react`) and raised hands are presence metadata (`hand`, `ht`) on the `aiws-room-<room>` channel; the deck lowers hands with a `lower` broadcast. They are ephemeral by design and never reach the export.
- Embedded live view: `src/join.html` iframes the deck as `../?view=1` (rendered at 1536×864, the smallest size where every slide fits, then scaled). `VIEW` decks are read-only (no keys, no presenter key, no net canvas), reuse the parent page's Supabase client (`window.AIWS.sb`) instead of opening a second socket, and apply presenter state from the `aiws-live-<room>` broadcast (`st` full snapshot on every change and every 5 s, `r` reaction batches, `hide`). Any new in-slide presenter control must be added to `Sync.snap`/`Sync.apply` in `src/deck.html`, or viewers will not see it. Thumbs go phone → REST broadcast → `aiws-react-<room>` (phones do not subscribe to it).
- Presenter inbox and announcements: `aiws_questions` is insert-only for anon (no SELECT grant); the notes page reads it every 4 s via `aiws_questions_list` and marks rows with `aiws_question_done`, both key-checked. The public message lives in `aiws_state.announce`/`announce_at` (set by `aiws_announce`) and reaches phones with the room state. Showing a question on screen goes notes → deck over the key-derived ctl channel (`{t:'q'}`), and the deck mirrors it to viewers as `qs` in the sync snapshot. `aiws_reset('all')` clears both. Questions are private: export them to `questions.csv`/`data.json`, never to `report.html`.
- Counting people: one person = same normalized name (no tashkeel, unified alef/ya/ta marbuta) in the same school, even across devices (`nameKey` in `src/deck.html`, mirrored in `scripts/export.mjs` and `scripts/school-reports.mjs`). The join slide counter (`.js-joined`) shows that deduped registered count, never presence: iOS drops the socket whenever the attendee switches to Zoom or locks the screen, so presence ("online now") only lives on the notes dashboard.
- Schools: partner schools (`partners.schools`) render on the partnership slide; `settings.extra_schools` (e.g. the volunteers school `vol`) only join the phone picker, roster and colours. Never show extra schools on the cover or partnership slide. School keys must match `^[a-z0-9-]{1,20}$` (DB check).
- Testing: the whole project runs in room `live-lab`, so `pnpm run build` is the test build. Never point it at `hs7-ai` or `hs7-ai-test`.
- Phone page layout: one column (560px, 720px from 700px wide); from 1000px wide and while the live view is shown, two columns (`.stage` beside `.side`). "Theater" (`body.watch.theater`) is the full-screen view with translucent reaction buttons. It opens only from the "ملء الشاشة" button and closes only with the X (`#theaterX`) or Esc; the device orientation is never watched (automatic landscape theater kept Safari's address bar visible, and rotating the device mid-view crashed Safari). On a portrait phone the view is CSS-rotated 90° (`rot`), decided once at entry; where the Fullscreen API exists (Android) the page also requests fullscreen and locks landscape, then recomputes `rot` once. Check 390, 768, 1024, 1366 and 1920 widths plus 844×390 after layout changes.
- Live audio feasibility test (LiveKit Cloud): `src/live-test.html` → `docs/live-test/` (listener; presenter adds `?p=1`, unlocked by the presenter key, reuses `localStorage.aiws_key` from the notes page). Copy in `content/22-live-test.md`. Tokens come from the Edge Function `supabase/functions/aiws_live_token` (deployed with `--no-verify-jwt`): presenter checked via `aiws_verify` and may publish; listener is subscribe-only with identity `l-<device id>`; LiveKit room `aiws-live-<room>`; only room `live-lab` is allowed. Secrets `LIVEKIT_URL`/`LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET` live in Supabase function secrets, local copy `secrets/livekit.env` (set with `supabase secrets set --env-file secrets/livekit.env --project-ref dqedhfwaquqaddbtfvtx`; never read or print the values). Every event goes to `aiws_live_probe` (insert-only for anon, migration in `supabase/migrations/`); drop it after the experiment. Listener audio plays through one `<audio>` element (`webAudioMix: false`) because background playback on iOS depends on it. Findings so far (iPhone iOS 18.3 Safari, Android Chrome): lock screen, a silent app and airplane mode keep or restore audio by themselves; after a phone call iOS leaves the element "playing" but silent, and only a full new connection revives it (re-attaching the track does not), so the page rejoins on return after any pause the user did not ask for. Known limit: the iOS lock-screen media widget's pause button never reaches the page (no Media Session action fires); the in-page stop button and volume keys are the way to silence it.
- Presenter audio in بوابة الحضور (round 2 of the LiveKit test; the portal link is the only link attendees get, so audio, slides and interaction all live there): the "دخول" tap in the name sheet starts audio (the browser's required gesture); a returning attendee with a saved name sees the `#audioGo` banner above the live view until she taps it; `#audioBtn` in the stage bar mutes/unmutes (choice kept in `aiws_audio`). Listener identity is `l-<device id without dashes, 24 chars>`; a second tab on the same device kicks the first, which stops and shows `audio_other` instead of reconnecting. After an unrequested pause (a phone call on iOS) the page reconnects LiveKit on return. The presenter still broadcasts from `live-test/?p=1`. The portal logs audio, visibility and Supabase channel status (`sb_phone`, `sb_room`) to `aiws_live_probe` with the school key as label, never the name. After a reload, a returning attendee (saved name, audio not muted) gets the `#gate` overlay, whose tap starts audio, because browsers never start audio without a gesture. Keeping the screen on while watching: Wake Lock plus, on iOS, the muted looping `assets/awake.mp4` (NoSleep technique); results go to the probe as `wake_*`. Copy: `join-page.audio_*`.
- `secrets/` (presenter key) is gitignored. Never commit it or print it into built files.
